## 3. 四个根因分别怎么改

v1 的 8 个 bug 不是 8 个独立错误，是 4 个根因：

### 根因 1：金额正则吃掉了日期

v1 用 `re.search(r'\d+(\.\d+)?', text)` 直接找第一段数字。`'2026-11-13 打车 30'` 最先撞到的是年份 `2026`，于是金额变成 2026 元。

改法：**先认日期、把日期片段从文本里删掉，再找金额**。顺序不能反。

```
原句 → 找日期片段（记下起止位置）→ 从文本里抠掉 → 在剩下的文本里找金额
```

要抠的日期形态：

- `2026-11-13`、`2026/11/13`
- `11月13日`、`11月13号`
- `今天`、`昨天`、`前天`、`明天`

### 根因 2：`_find_date` 完全不认显式日期

v1 只认昨天/前天/明天，`day` 永远是今天附近。所以 `'2026-11-13 打车 30'` 的日期也是错的。

改法：按优先级认，认到就返回：

1. `YYYY-MM-DD` / `YYYY/M/D`
2. `M月D日` / `M月D号`——年份取 `today.year`；如果算出来的日期比今天晚，**仍然取今年**（不跨年推断，保持简单，遇到跨年再说）
3. 今天（`1`）、昨天（`-1`）、前天（`-2`）、明天（`+1`）
4. 都认不到 → 返回今天

返回值一律 `date.isoformat()`，别用 `str(today)`——如果传进来的是 `datetime`，`str()` 会带 `' 00:00:00'`，格式就不是 `YYYY-MM-DD` 了。

### 根因 3：类别里的 `break` 只跳出内层循环

```python
for cat, keywords in CATEGORIES.items():
    for kw in keywords:
        if kw in text:
            category = cat
            break          # 只跳出内层，外层继续，最后匹配的赢
```

结果就是「打车去吃饭」判成交通、「买了一杯奶茶」判成购物。

改法：**不要用「最后一个赢」，改成打分**：

1. 遍历 8 个类别（含「其他」，但它没有关键词，永远 0 分）；
2. 每命中一个关键词，把**关键词长度**加进这个类别的分（`吃` 加 1，`吃饭` 加 2，`奶茶` 加 2）；
3. 取分数最高的类别；
4. 最高分是 0 → `"其他"`；并列 → 也给 `"其他"`（宁可判不出来，也别乱猜）。

为什么按长度累加而不是命中个数：`'打车去吃饭 50'` 里交通命中「打车」=2 分，餐饮命中「吃」+「饭」+「吃饭」=1+1+2=4 分，餐饮赢；`'买了一杯奶茶 18'` 里购物「买」=1 分，餐饮「奶茶」=2 分，餐饮赢。用命中个数则前者 1:1 并列、后者 1:1 并列，两个都判不出来。

### 根因 4：`_find_range` 把「上个月」当成 today-30 天

契约 v2 第三节 `_find_range` 的说明写死了：**「上个月」必须是 2026-10-01 ~ 2026-10-31，不是 today-30 天**。另外 v1 没有「最近 30 天」分支，所以 `'最近30天消费多少'` 退化成今天一天。

## 5. 金额怎么换算成分（不许用 float）

`30.5 元` 要变成 `3050`。**不要写 `int(30.5 * 100)`**——浮点数会给你 `3049.9999999999995`，`int()` 一截就成 3049。

两种安全写法，任选一种：

- 按字符串拆：`'30.5'.split('.')` → 整数部分 `30`、小数部分 `5`，小数补成两位 `50`，结果 `30*100 + 50`；
- 或者 `Decimal('30.5') * 100` 再取整。

中文数字只在**后面跟着单位**时才当金额：「二十块」→ 2000、「三十元」→ 3000。单独一个「一」「两」不算——`'买了一本书'` 的 1 是量词，不是钱。这条就是 bug 列表里 `amount=1.0` 的来源。

一句话里同时有「三十块」和「2026」时，先抠日期（根因 1），再按单位找金额。

中文数字部分可以用 `cn2an`（见第 11 节），但它只替掉「中文数字 → 整数」这一步，单位和日期规则不变。

## 9. 常见坑（对照自查）

1. `str(datetime(...))` 会带时分秒 → 用 `.date().isoformat()`。
2. 金额用 `float * 100` 会出现 3049.999… → 按字符串拆或 `Decimal`。
3. 类别匹配 `break` 只跳内层 → 打分，不 break。
4. 日期没补零：`2026-11-5` 会让那笔账在 SQL 里静默漏掉 → 用 `f"{y:04d}-{m:02d}-{d:02d}"`。
5. 先找金额后抠日期 → 年份被当金额。
6. 把「上个月」写成 `today - 30 天`。
7. 单独的中文「一」「两」被当金额。
8. 在 `parser.py` 里 `import db` 或 `import main` → 死循环/启动报错，parser 必须独立。

### 11.1 它能做什么、不能做什么（沙箱实测 0.5.24）

### 11.2 写法（顶部兜底 + 只在 cn_to_int 内用）

> 下面的兜底写法已被 11.5 取消，保留仅作说明；现在直接 `import cn2an` 即可。

```python
try:
    import cn2an          # 可选依赖：装了就用，没装也不能让服务起不来
except ImportError:
    cn2an = None

def cn_to_int(text):
    """中文数字转整数。转不了返回 None。"""
    if not text:
        return None
    if cn2an is not None:
        try:
            return int(cn2an.cn2an(text, "smart"))
        except Exception:   # 「块」这类单位会抛 ValueError，交给手写逻辑
            pass
    return _cn_to_int_manual(text)
```

要点：

- 不要写光秃秃的 `import cn2an`。模块一被 import 就执行，别人环境没装 → `ModuleNotFoundError` → `main.py` 导入失败 → uvicorn 起不来，页面和 11 条接口全挂。

- 调用处再包一层 `try/except`，因为 cn2an 对带单位的字符串会抛 `ValueError`。
- 手写的 `_cn_to_int_manual` 要留着，作为没装包时的退路，也是自测覆盖的对象。

1. 只把**纯中文数字片段**喂给它。先用 `([一二两三四五六七八九十百千万零〇]+)\s*(块|元|钱)` 把数字和单位切开，数字部分再转。

3. 「一」「两」这类量词照旧不算钱：**后面必须跟单位**才当金额。这条在调用 cn2an 之前判断，不能省。

## 12. 组长补充：关键词表与验收口径（2026-11-18 晚）

> 这一节在第 11 节之后追加。**和第 3 节根因 3、第 7 节用例一起看；和前面的内容冲突时，以本节为准。**

### 12.1 关键词一律至少两个字

`CATEGORIES` 里每个关键词**至少两个字**，删掉所有单字词。v1 里下面这些必须去掉：

```
餐饮：饭、吃、喝、餐      交通：车      购物：买、鞋      娱乐：玩
```

原因：单字词藏在别的词里，会让**同一段文字被重复计分**。交通表里同时有「打车」和「车」，句子「打车 30」里「车」再得 1 分，交通白拿分；「买」会命中「买单」「买一送一」，「玩」会命中「玩手机」。

代价与应对：删掉「吃」之后，「吃了个包子 5」可能判不出类别。**这是可以接受的**，判「其他」即可，不要为个别句子把单字词加回来。要提高覆盖就补二字词：`吃饭`、`餐厅`、`包子`、`打车`、`奶茶`。

### 12.2 判不出来就给「其他」，不许硬猜

- 「其他」没有关键词，永远是 0 分。
- 最高分是 0 → `其他`；最高分并列 → 也判 `其他`。
- 这两种情况 `understood.category` 必须是 `False`，让前端把这一格标黄给用户改。
- **不许**为了「让用例过」在并列时随便挑一个类别；也**不许**因为「以后有大模型兜底」就放宽这条。大模型兜底不在本轮范围（`back-ai` 分支目前只有 `.gitignore` 和 `README.md`），本轮判不出来就是「其他」。

### 12.3 常见词必须判对，「其他」不能变成万能答案

判不出来给「其他」可以，但下面这些高频、无歧义的词必须出现在词表里，PR 里要核对得到：

```
餐饮：吃饭、外卖、奶茶、火锅、麦当劳、肯德基
交通：打车、公交、地铁、高铁、滴滴、油费
购物：超市、淘宝、京东、衣服、日用品
居住：房租、水电、物业、宽带、燃气
娱乐：电影、游戏、旅游、唱歌
健康医疗：医院、药店、挂号、体检、看病
学习教育：学费、课程、文具、教材、培训
```

如果大部分账都落进「其他」，分类统计就失去意义，组长会在 PR 里打回。

### 12.4 「大前天」= 减 3 天，必须排在「前天」之前

- 原因：`"前天" in "大前天"` 是 `True`，`in` 是包含匹配。若「前天」的判断在前，「大前天」会被算成减 2 天，**日期静默错一天**。
- 要求：在判断「前天」**之前**先判断「大前天」，返回 `today - timedelta(days=3)`。
- 对应第 7 节第 15 条用例。这条是 2026-11-18 晚新增的，原单没有。

### 12.5 日期正则只写一份

日期长相只用一套 `re` 模式，定义在文件顶部当常量，`_find_date` 和 `parse_text`（抠日期时）**引用同一份**。不允许两处各写一个相似但不同的正则。

反例：`_find_date` 认「11月13号」，`parse_text` 只认「11月13日」。现象是「11月13号 吃饭 30」日期对了、金额却变成 11 元，而且不报错。

### 12.6 PR 里必须贴出完整关键词表

第 10 节原有的「列出新增的关键词」升级为硬要求：**PR 描述里贴出完整 `CATEGORIES`（7 个支出类别的全部关键词），不是只列新增的。** 组长按 12.1、12.3 逐条核对。这条也算第 10 节的完成标准之一。

### 12.7 必须有一条收入用例（第 16 条）

原来的 15 条用例里**一条收入句子都没有**，这意味着把 `type` 写死成 `"expense"` 也能全绿——收入功能一天没写，验收照样通过。所以补第 16 条：

```
「工资到账 8000」-> type=income，category=收入，amount=800000，understood.type=True
```

配套口径：

- 句子出现「工资 / 薪水 / 生活费 / 红包 / 兼职 / 报销 / 退款 / 奖金 / 利息 / 到账」等词 → `type=income`，`category` 固定 `"收入"`，`understood.type=True`。
- 没有收入词 → `type=expense`，**`understood.type=False`**（默认值必须标出来，见第 2 节）。
- 第 10 条和第 16 条是一对：第 10 条证「没有收入词时如实标 False」，第 16 条证「有收入词时真的能认出来」。两条都过，才能说明 `type` 不是硬编码的。

### 12.8 `understood` 的 True 只表示「认到了」，不表示「结果对」

这条是 2026-11-18 晚发现的笔误，写下来防止再犯：

- `understood.xxx = True`：这句话里**确实有这个信息**，是我识别出来的。
- `understood.xxx = False`：句子里没有，我用了默认值。

「结果看起来对」不等于「认到了」。例：「昨天打车 23 块」是支出的概率很高，但句子里没有表达收支的词，`type` 就是默认值，必须标 `False`。前端靠这个标记决定哪一格标黄让用户确认。
